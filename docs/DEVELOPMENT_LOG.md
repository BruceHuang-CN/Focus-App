# Focus 开发日志

本文件记录开发过程中发现的问题、根因分析与修复，随代码一并提交到仓库。

---

## 2026-08-14（检测与稍后提醒可靠性修复）

### 现象

- 兼容模式偶尔漏掉目标 App 的切换，额度仍有但不再弹窗。
- 选择 1/3/5 分钟稍后提醒后，进程被回收时任务可能不再执行。
- 实时模式下，应用内无障碍开关与系统真实授权状态可能不一致。

### 根因与修复

- 使用情况检测改为 30 秒重叠查询，并按时间戳和包名去重，避免严格时间窗口漏掉延迟写入的切换事件。
- 兼容检测服务改为 `START_STICKY`，普通进程回收后允许系统重建服务。
- 稍后提醒截止时间写入 Room；应用重启后恢复未到期或已到期任务，并以原子领取避免重复弹窗。
- 启动时可接续同一目标 App 的近期未关闭会话，避免恢复任务被初始化流程立即取消。
- 应用内无障碍开关保留为用户偏好，系统授权单独读取；只有两者都开启时才运行实时守护，返回设置页时不再强行覆盖用户选择。

### 系统限制

ColorOS 等系统的后台策略如果对 Focus 执行真正的 `force-stop`，Android 会停止服务、闹钟和任务调度；应用无法在被强行停止后自行恢复。需要用户在系统后台/自启动设置中允许 Focus 运行。普通进程回收已通过上述恢复机制处理。

## 2026-08-08（常驻守护）

### 问题：实时模式下进程被系统回收，提醒失效、最近任务中消失

即使锁定了 Focus，系统仍可能回收进程；锁定只防止误删最近任务，不能保活。

**实现**：

- 新增低打扰前台服务 `KeepAliveService`（仅保活、零轮询），实时模式开启时运行，
  展示一条低优先级常驻通知。
- 设置页「检测方式」新增「常驻守护」开关（默认开启），用户可自行关闭；
  开关变化即时生效，MainActivity 根据检测方式 + 无障碍开关 + 常驻开关自动启停服务。
- 常驻通知可被用户折叠/隐藏，不影响提醒功能。

## 2026-08-08（修复）

### 问题：首页统计/提醒记录为空、统计图表不显示、文字看不清

**现象**：首页打开次数、主动退出、提醒记录全部为 0/空；统计页只有打开次数有值，
三个图表显示"暂无数据"；统计与首页文字颜色与背景太接近看不清。

**根因**：

1. 首页仍从旧的 `app_usage_events` 表读取统计与提醒记录，而检测流程已全面改用
   `app_usage_sessions` 表，旧表无人写入 → 数据恒为 0/空。
2. 图表时长按分钟向下取整，测试时打开应用只有几秒 → 0 分钟 → 图表无数据。
3. 全局次要文字色 `outline` 过浅（#D8D2C3），与背景对比度不足。

**修复**：

- 首页统计与最近提醒记录改为读取会话表，与统计页数据源一致。
- 统计时长改为向上取整（至少 1 分钟），短时打开也能出图。
- 全局次要文字颜色调深（outline = #6F6A5F），提升可读性。

## 2026-08-08

### 功能与修复

- **目标 App 列表看不到部分应用**：Android 11+ 包可见性限制导致应用列表被过滤。
  在 AndroidManifest 增加 `<queries>` 声明（MAIN/LAUNCHER intent），
  使抖音、小红书、哔哩哔哩等带启动入口的应用可被列出。
- **呼吸停顿开关找回**：设置页「提醒时间」重新加入「提醒前呼吸停顿」开关，
  由用户自行选择是否在弹窗前先深呼吸（之前重构设置页时该开关被遗漏）。
- **返回行为支持指定应用**：返回行为新增「返回指定应用」选项，填写目标包名后，
  提醒弹窗的主动退出按钮会跳转到该应用；包名无效时回退到桌面。
- **返回指定应用改为按名称选择**：不再要求用户输入包名，改为从已安装应用列表
  按应用名称选择（与目标 App 选择同一套交互），包名在内部自动保存。

## 2026-08-07（补充）

### 功能：提醒额度可视化、额度重置与半手动保存

**背景**：窗口内提醒额度用尽时提醒被静默跳过，用户不知道原因；
设置页每次改动都弹"已自动保存"，缺少操作感。

**实现**：

- 提醒弹窗新增一行"本窗口（X 分钟）已提醒 X/Y 次"，展示当前额度使用情况。
- 设置页「提醒次数」分组新增「重置当前窗口额度并重新生成提醒」按钮：
  清空当前窗口内的已提醒标记，并通过缓存刷新信号让 AI 在后台重新生成目标 App 的提醒文案。
- 设置页改为半手动保存（B 方案）：改动仍即时保存，但不再弹"已自动保存"提示，
  顶部显示"有未保存的修改"状态与「保存设置」按钮，提供确认操作感。

## 2026-08-07

### 功能：设置页「检测状态」权限检查窗口

**背景**：实时模式不触发提醒时，应用没有任何反馈，用户无法判断是哪一环权限缺失。

**实现**：

- 设置页顶部新增可展开的「检测状态」窗口，按当前检测方式列出所需权限检查项，
  每项显示 ✓/✗ 与「去开启」入口，点击跳转对应的系统设置或应用内开关。
- 实时模式检查：系统无障碍服务、应用内「启用无障碍检测」、通知权限、
  显示在其他应用上层、目标 App。
- 兼容模式检查：使用情况访问权限、通知权限、显示在其他应用上层、目标 App。
- 从系统设置返回时自动刷新检查结果。
- 检查逻辑为纯函数 `PermissionCheckEvaluator`，配套单元测试与 UI 测试。

## 2026-08-06

### 问题 1：提醒弹窗不出现（真机实测）

**现象**：安装后页面显示正常，但打开目标 App 后没有任何提醒弹窗；首次打开 App 时也没有权限提示。

**根因分析**（按调用链逐层排查）：

1. 引导页选择检测方式后，只跳转系统设置页并标记引导完成，**没有把所选模式写入应用设置**。
   `enableAccessibility` 默认值为 `false`，且唯一的写入点是设置页的「启用无障碍检测」开关。
2. `FocusAccessibilityService.shouldProcessAccessibilityEvents()` 要求
   `detectionMode == REALTIME && enableAccessibility` 同时成立；开关为 false 时，
   无障碍事件在入口被直接丢弃 → 不产生会话 → 不触发提醒。
3. 兼容模式同理：`MainActivity` 仅在 `detectionMode == COMPATIBILITY` 时启动检测服务，
   引导页同样没有写入该值，服务不会启动。
4. 「首次打开无权限提示」符合当前设计（应用不主动请求权限，仅由引导按钮跳系统页）；
   一旦完成过引导（SharedPreferences 标记），之后直接进入首页。

**修复**：

- 引导页选择检测方式时即调用 `SettingsViewModel.applyOnboardingDetectionMode(mode)`，
  持久化 `detectionMode` 与 `enableAccessibility`。
- 设置页监听生命周期：实时模式下若系统无障碍已开启，自动把应用内开关置为开启
  （`ensureAccessibilityEnabled()`），即使之前没手动开开关也能恢复检测。
- 「启用无障碍检测」开关与实时模式选中时，未开启则跳转系统无障碍设置页。
- 引导页进入 AI 配置步骤时（Android 13+）请求通知权限，实时模式同样覆盖。

### 问题 2：弹窗可能被静默吞掉（悬浮窗与通知权限）

**现象**：即使检测链路通了，也可能看不到任何提醒。

**根因分析**：

1. 提醒展示依赖「显示在其他应用上层」（SYSTEM_ALERT_WINDOW），
   无权限时降级为通知；但应用内**没有任何地方引导用户开启悬浮窗权限**。
2. Android 13+ 通知需要运行时权限，实时模式路径此前不会请求通知权限；
   通知被拒绝时降级通知也会被系统丢弃。

**修复**：

- `PermissionHelper` 增加悬浮窗权限检测与跳转（`ACTION_MANAGE_OVERLAY_PERMISSION`）。
- 设置页「检测方式」分组新增悬浮窗权限状态行与「去开启」入口，并在返回页面时刷新状态。
- 切换到任一检测方式时都会请求通知权限（Android 13+）。

**验证方式**：Android Studio 构建后真机复测——目标 App 打开后停留超过提醒延迟，
应出现悬浮窗弹窗或通知；首次引导完成后检查设置中的检测方式与无障碍开关状态。
