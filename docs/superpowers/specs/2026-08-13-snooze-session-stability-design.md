# 稍后提醒会话稳定性设计

## 目标

修复稍后提醒因为 Focus 自身窗口、输入法、权限窗口或通知栏等短暂前台变化而被提前取消的问题，同时保持用户确认的行为：真正离开目标 App 后，本次稍后提醒不再出现。

## 已确认行为

- 稍后提醒只在用户持续使用触发提醒的原目标 App 时有效。
- 用户选择 1/5/10 分钟或自定义分钟后，提醒页关闭并返回原目标 App，继续同一会话计时。
- Focus 提醒 Activity、键盘、权限窗口、通知栏和短暂系统窗口不视为真正离开。
- 用户切换到桌面或其他普通 App，经过短暂复核后仍未回到目标 App，则结束会话并取消本次稍后提醒。
- 到期时用户不在原目标 App，不发通知，也不弹窗。
- Android 或 Android Studio 强制停止 Focus 后，系统不会允许应用自行恢复服务或执行 WorkManager；本次设计不尝试绕过该限制。

## 方案比较

### 采用：疑似离开后单次延迟复核

收到非目标包名事件后，不立即关闭会话。创建一个短暂的待确认任务；1.5 秒后通过现有前台验证能力确认目标 App 是否仍在前台。已恢复则保留会话，仍为其他 App 才结束会话。

优点是不用维护厂商系统包名白名单，也不增加持续轮询。它能覆盖 Focus 自身透明 Activity 和大部分短暂系统窗口。

### 不采用：仅在 WorkManager 到期时检查

实现最少，但用户离开后再于到期前返回目标 App 时仍可能收到提醒，不符合“真正离开即取消”的语义，而且会留下不必要的等待任务。

### 不采用：系统窗口包名白名单

代码简单，但不同 Android 厂商和输入法的包名差异很大，长期维护成本高，仍会漏判。

## 组件边界

### AppSessionCoordinator

- 保持当前目标 App 会话和前台包名的唯一协调入口。
- 增加可取消的“疑似离开”任务；同一时刻最多存在一个。
- 生产环境使用进程级可取消协程作用域；测试注入测试作用域和虚拟时间，不阻塞检测服务事件队列。
- 目标 App 的新事件、提醒展示事件或新的会话会取消过期确认任务。
- 只有确认真实离开后，才关闭会话并调用现有调度取消入口。
- `stopCurrentSession()` 属于用户关闭守护、额度重置或应用组切换等显式停止路径，继续立即关闭，不等待复核。

### 前台验证

- 复用检测服务现有的 `foregroundVerifier`，不新增常驻服务。
- 无障碍实时模式优先依据随后到达的窗口事件和现有前台状态。
- 兼容模式复用 UsageStats 前台检查。
- 若验证能力不可用或返回不确定，按新的前台事件处理；不把未知状态当作目标 App 仍在前台。

### ReminderScheduler 与 FollowUpReminderWorker

- 首次提醒和稍后提醒继续绑定同一个使用会话。
- 真正离开后，当前取消入口同时停止首次延迟与稍后提醒，这是预期行为。
- Worker 到期时继续检查守护开关、目标应用配置、原会话仍打开且当前、目标 App 真实前台和额度。
- 不增加周期任务；稍后提醒仍使用一次性 WorkManager。

## 数据流

1. 用户进入抖音，协调器创建会话并安排首次提醒。
2. 提醒出现，用户选择“稍后 3 分钟”，一次性 WorkManager 任务绑定当前会话。
3. ReminderActivity 关闭时产生 Focus 或系统窗口事件，协调器进入疑似离开状态。
4. 抖音在复核前恢复前台：取消疑似离开任务，保留会话与 3 分钟任务。
5. 用户真正切换桌面或其他 App：复核后关闭会话并取消 3 分钟任务。
6. 3 分钟到期时再次验证；仅当原会话和抖音前台都有效时才展示提醒并消耗额度。

## 并发与异常处理

- 使用现有协调器互斥锁保护会话、前台包名和待确认任务的状态变化。
- 每个确认任务带有会话 ID 或事件版本；旧任务醒来后发现版本已变化即退出，不能关闭新会话。
- 新的目标 App 事件必须先作废旧确认，再进行相同包名去重。
- 协调器显式停止时取消待确认任务，避免守护关闭后旧任务继续运行。
- 延迟复核只存在于应用进程内；进程普通回收后，WorkManager 到期检查仍会拒绝已无效会话。系统强制停止则遵循 Android 限制。

## 测试

1. 非目标包名短暂出现，目标 App 在复核前恢复：会话保持打开，调度器不取消。
2. 非目标包名持续超过复核时间：会话关闭，首次/稍后提醒被取消。
3. 快速连续切换产生多个确认任务：只有最新事件有效，旧任务不能关闭新会话。
4. `stopCurrentSession()`：立即取消待确认与提醒并关闭会话。
5. 自定义 3 分钟在持续停留目标 App 时到期展示。
6. 3 分钟内真正离开目标 App：WorkManager 被取消，到期不展示、不消耗额度。
7. 现有提醒展示保护、额度和前台复核测试继续通过。

## 范围限制

- 本轮不修改提醒额度数据模型、养成系统、统计图表或 DeepSeek 文案生成。
- 本轮不新增后台常驻轮询、AlarmManager 或厂商专用白名单。
- 本轮不承诺绕过系统强制停止或厂商禁止后台运行。
