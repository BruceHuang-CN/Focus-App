# Focus 监测与稍后提醒稳定性修复设计

## 目标

修复兼容模式漏掉应用切换、后台服务普通回收后不恢复、稍后提醒到期不执行，以及实时模式显示的无障碍状态与系统不一致的问题。用户主动离开原目标应用后，不再显示该会话的稍后提醒；切换到另一个目标应用时，应为新应用建立独立会话并按额度提醒。

## 已确认的根因

- 兼容模式每 10 秒查询一次互不重叠的 `UsageEvents` 时间窗口。系统延迟写入事件时，事件时间戳可能落在已查询窗口中，从而被永久遗漏。
- `AppDetectionService` 返回 `START_NOT_STICKY`，被普通回收后不会由系统恢复。ColorOS 的明确“强制停止”仍属于 Android 平台不可绕过的边界。
- WorkManager 只保证延后执行，不保证 1/5/10 分钟的准点执行；当前稍后提醒缺少可恢复的业务到期状态。
- 应用保存的 `enableAccessibility` 只是历史选择，不代表系统无障碍服务当前确实已启用。

## 方案

### 1. 兼容模式检测

保留低频轮询，但每次查询带重叠的滚动窗口，并以“事件时间戳 + 包名”去重。这样不增加持续高频扫描，也能接住系统延迟写入的前台事件。检测到离开当前目标应用后，经现有 1.5 秒确认逻辑关闭旧会话；若新前台也是目标应用，立即建立新会话。

### 2. 服务恢复

兼容模式前台服务改为 `START_STICKY`。服务重建后重新读取守护开关和检测模式；只有“兼容模式且守护开启”时继续轮询，否则自行停止。普通系统回收可以恢复，用户或系统管家执行真正的 force-stop 后仍需用户重新打开 Focus，这是 Android 安全限制。

### 3. 稍后提醒

在会话中持久化稍后提醒到期时间，调度器仍使用进程内协程提供准点体验，WorkManager 仅作进程死亡兜底。应用或监测服务恢复时重新装载未到期任务；已到期任务立即经过统一 Gate 判断。Gate 必须确认守护开启、会话仍开放、当前仍是同一目标应用且额度充足。离开原目标应用时关闭会话并取消任务。

### 4. 无障碍真实状态

实时模式入口读取 Android 当前已启用的无障碍服务列表，而不是只读取数据库字段。系统服务未启用时，首页和设置页明确显示未启用并引导进入系统设置；重新安装或系统关闭无障碍后不得继续显示“已开启”。

## 错误处理与诊断

为会话开始、前台切换、稍后提醒创建/恢复/取消/执行和 Gate 拒绝原因增加受控诊断日志，不记录任务正文、API Key 或 AI 提醒内容。日志只用于 Android Studio Logcat 排查。

## 测试边界

- 延迟到达但时间戳落在重叠窗口内的事件只处理一次。
- 从目标 A 切换到目标 B 时关闭 A、取消 A 的稍后提醒并创建 B。
- 服务重建后在正确模式恢复，守护关闭或实时模式不启动兼容轮询。
- 稍后提醒在进程恢复后重新调度；离开目标应用后不显示。
- 数据库开关为真但系统无障碍关闭时，界面状态必须为关闭。

## 非目标

本轮不增加新的提醒选项、不修改 AI/DeepSeek 接口、不调整统计图表和养成系统、不尝试绕过 Android 的 force-stop 限制。
