# 提醒交互收尾设计

## 目标

根据 realme RMX3350 真机反馈，修复提醒操作菜单的锚点、稍后提醒通知栏倒计时、提醒全屏覆盖和“回到任务”的目标页，让每次提醒的视觉与跳转结果可预期。

## 已确认的行为

1. 每次提醒均以全屏、不透明的提醒内容覆盖目标应用；不再按窗口内第几次提醒缩小卡片。最后一次提醒仍保留既有的文案和颜色升级，但不再是唯一的全屏提醒。
2. 点击「有目的使用」或「休息一下」时，1/5/10 分钟和自定义分钟数菜单必须紧贴被点击的那个按钮展开。菜单的打开状态仅是该按钮组件的短暂本地 UI 状态；自定义输入框的动作类型仍由提醒页面持有，以便显示正确标题并调用既有稍后提醒链路。
3. 稍后提醒倒计时继续使用原有 `snoozeUntil`、协程、WorkManager 和 AlarmManager 作为真实调度来源。通知只显示状态：改用新的、正常重要性、无声音无振动的通知频道，确保 ColorOS 不把它归为低重要性静默条目；取消、重新安排和到期时仍清除通知。通知权限未授予时不得影响弹窗调度。
4. 「回到任务」始终打开 Focus 的 `tasks` 标签页，忽略旧的 `ReturnDestination` 设置。该设置不影响本轮的「有目的使用」和「休息一下」；二者仍仅安排稍后提醒并记录各自动作。

## 最小实现边界

- 不新增依赖、不新增 Activity，不更改数据库或提醒额度语义。
- 保留现有三个动作、六种稳定排列、1/5/10 分钟及 1～60 分钟自定义输入。
- 不删除旧通知频道；Android 对已创建频道的用户设置不可由应用可靠覆盖，因此新增频道 ID 承载新的默认重要性。
- 不把“通知可见”误写成“提醒可靠”：OEM 后台限制、锁屏和到期弹窗仍需真机回归。

## 代码边界

- `ReminderUrgency.kt`：卡片始终使用 `1f` 宽高，保留最后一次标志用于文案/颜色。
- `ReminderDecisionButtons.kt`：每个定时动作按钮包裹自己的 `DropdownMenu`；组件把分钟和自定义动作回调给父页面。
- `ReminderOverlay.kt`：删除共享外层菜单，只保留自定义输入框及对 ViewModel 的已有调用。
- `FollowUpCountdownNotifier.kt`：升级至新的正常重要性倒计时频道；仍静音、持续展示、使用系统 Chronometer。
- `MainActivity.kt` 与 `NavGraph.kt`：读取“打开任务页”启动请求，并在新 Intent 到达时导航到 `tasks`。
- `ReminderLauncher.kt`：`returnToFocus` 请求任务页而非首页。

## 验收与测试

- JVM：全屏尺寸策略恒为 `1f`；“回到任务”启动请求解析为 `tasks`；既有调度测试仍验证倒计时显示与取消。
- Compose AndroidTest：点击每个定时按钮只打开其自己的时长菜单；选择分钟数或自定义入口传回正确动作。
- 构建：运行 JVM 测试、AndroidTest 源码编译和 Debug APK 构建。
- 真机：选择 5 分钟后通知栏出现可见倒计时；点击两个定时按钮检查菜单贴合；从提醒点「回到任务」确认底部“任务”标签页已选中；首个和后续提醒均铺满屏幕。
