# 三项提醒操作与稳定随机顺序设计

## 目标

把现有“退出目标应用 / 稍后提醒”改为三个始终可见的明确选择：`RETURN`（回到任务）、`INTENTIONAL`（有目的使用）、`REST`（休息一下）。三个选择默认采用六种完整排列之一，并在同一次提醒生命周期中保持稳定。

## 行为语义

- `RETURN`：按设置中已有的 `ReturnDestination` 直接返回 Focus、桌面或指定应用，并记录现有返回行为。
- `INTENTIONAL`：选择 1、5、10 或自定义分钟，记录 `intentional_<n>m`，立即关闭弹窗，沿用现有 `snoozeUntil`、混合调度和通知栏倒计时；到期复核前台后决定展示、跳过或重试。
- `REST`：选择 1、5、10 或自定义分钟，记录 `rest_<n>m`，其计时、关闭和到期复核行为与 `INTENTIONAL` 共用同一可靠链路。本阶段不新增全局暂停。
- `Ignore` 不作为第四个按钮；无响应、绕过、展示失败或未知证据不在本阶段被错误写成用户选择。

## 顺序

- 固定顺序为 `RETURN, INTENTIONAL, REST`。
- 随机开关开启时，从三个动作的六种排列中选择一个。
- 选择结果由已经持久化并随提醒 Intent 传递的 `attemptId` 稳定映射；相同 `attemptId` 必须得到相同顺序，不依赖 Compose `remember` 的进程内寿命。
- 随机开关关闭时使用固定顺序。
- 设置使用 `focus_prefs` 中的独立布尔值，缺失时读取为 `true`，覆盖新装和升级用户默认开启要求。

## UI

- 三个按钮纵向全宽排列，避免窄屏下“有目的使用”换行拥挤。
- `RETURN` 使用主按钮；`INTENTIONAL` 使用 tonal 按钮；`REST` 使用描边按钮。样式跟随语义，位置可以随机。
- 两个计时动作各自打开同一套时长菜单，自定义对话框标题随当前动作变化。
- 顺序属于派生的只读 UI 状态；菜单展开、自定义对话框和输入值保持在 `ReminderOverlay` 的最低必要状态所有者。

## 非目标

- 不新增全局休息模式、目的文本输入、AI 原因生成或新的 Room 表。
- 不修改提醒额度、前台检测、锁屏重试与双开应用检测。
- 不在本阶段推断或聚合 Ignore 指标。

## 验收

- 关闭随机时顺序固定；开启随机时只有六种合法排列，同一 seed 永远稳定。
- `INTENTIONAL` 与 `REST` 分别记录不同动作，但使用相同的分钟校验、截止时间持久化、调度与倒计时通知。
- `RETURN` 正确分派到已配置目标，自定义应用失败时弹窗保持打开。
- 设置未写入时默认随机，用户关闭后持续固定。
- 定向测试、完整单元测试和 Debug 构建通过；布局与 OEM 行为标记为待真机验证。
