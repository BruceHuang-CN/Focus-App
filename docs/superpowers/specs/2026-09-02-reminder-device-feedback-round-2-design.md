# 第二轮真机提醒反馈设计

## 目标

修复 RMX3350 手动回归中确认的四项问题：稍后提醒倒计时只进入通知栏而不显示顶部横幅、定时选择菜单未相对按钮居中、从设置页点击底部菜单时绕过保存确认，以及强制提醒被 Home/上滑隐藏后无法再次出现。

## 已确认行为

### 倒计时通知

- 用户需要的是通知出现时在当前界面顶部显示一次 Heads-up 横幅，不是自动打开 Focus Activity。
- 使用新频道 `focus_follow_up_countdown_v3`；旧频道保留，因为 Android 不允许应用可靠覆盖已创建频道的重要性。
- 新频道使用 `IMPORTANCE_HIGH`，通知使用 `PRIORITY_HIGH` 和系统默认通知声音；`setOnlyAlertOnce(true)` 保证只在倒计时开始时提示一次。
- 通知继续使用系统倒计时、保持 ongoing；真正到期调度仍由现有协程、AlarmManager 与 WorkManager 负责。
- 通知权限缺失或频道被用户关闭时，不得影响真正的稍后提醒调度。

### 定时菜单

- 「有目的使用」与「休息一下」继续各自拥有独立菜单锚点。
- 菜单固定为足够容纳最长文案的宽度，并在按钮可用宽度内计算水平居中偏移；窄屏时偏移不小于零。
- 菜单仍优先由 Material `DropdownMenu` 决定显示在按钮下方或上方，不自行实现窗口边界算法。

### 设置页离开确认

- 设置修改标记提升到 `NavGraph`，因为设置页与底部导航是兄弟节点，局部状态无法拦截底栏点击。
- 系统返回、左上角返回和底部菜单切换使用同一个离开确认窗口。
- 点击「保存并切换」后清除修改标记并前往用户刚才选择的标签；点击「继续修改」则留在设置页。
- 当前设置项大多在交互时已经持久化；本轮保持现有半手动确认语义，不扩展为完整草稿系统。

### 强制提醒待选择状态

- 普通应用不拦截系统 Home/最近任务手势。强制提醒被 Home、上滑或系统界面隐藏时，若用户未选择任何操作，则从“正在显示”转换为“等待重新显示”。
- 启动中、正在显示与待选择状态分离；待选择仍保护原目标 App 会话，但不能再被误认为 Activity 当前可见。启动失败会恢复为待选择，启动中状态超时后也允许再次尝试。
- 再次观察到同一目标包名处于前台时，用新的 `attemptId` 重新显示同一次待选择提醒。
- 每一次 ReminderActivity 真正完成首帧绘制后都记录一条独立展示事件、消耗一次额度；重显也一样。首帧到记账确认完成之间按钮暂时不可操作，避免已经执行选择却漏记本次展示。
- Activity 停止或收到新的 `singleInstance` Intent 时取消旧展示确认；异步结果只有在 Activity 仍为 RESUMED、Intent attempt 与注册表 attempt 都匹配时才能提交，旧 attempt 不能清除或覆盖新 attempt。
- 待选择重显不受普通窗口额度阻止，即使计数已达到或超过上限，也必须继续显示，直到用户选择「回到任务」「有目的使用」或「休息一下」。普通新提醒仍受额度限制。
- 只发通知而 Activity 未显示时不记展示事件。
- 本轮只保证进程存活期间的待选择重显；不新增数据库字段，不把个人手机改为 kiosk/设备所有者模式。

## 最小实现边界

- 不新增第三方依赖、不新增 Activity、不增加轮询频率。
- 不安装 APK、不执行 connected AndroidTest、不自动操作手机；本轮只运行本地 JVM 测试和源码编译级验证。
- 复用现有 `ReminderDisplayRepository` 的独立展示事件表；强制重显通过新的展示类型和唯一 attempt ID 记账。
- 保留稍后提醒的 snooze 转场保护，用户已经选择稍后提醒时不得再次进入待选择状态。

## 验收

1. 选择 5 分钟后，顶部出现一次倒计时通知横幅，通知栏继续递减且不会反复响铃。
2. 两个定时按钮的菜单分别在对应按钮下方水平居中。
3. 设置页修改后点击任意其他底部标签，先出现保存确认；确认后进入正确标签。
4. 强制提醒出现后上滑回桌面，再次进入原目标 App 时重新显示；每次显示计数加一，即使超过普通额度也继续，直到选择一个操作。
