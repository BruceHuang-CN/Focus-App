# 回到任务后重复提醒：源码修复与验收清单

日期：2026-09-10。目录：`D:\Project\Focus-App-UI-improve`，分支：`codex/ui-optimization`。

## 证据与问题范围

此前采集的设备 events 日志显示，19:14:36.917 旧 ReminderActivity 销毁，36.961 MainActivity 恢复，37.126 又创建一个 ReminderActivity。确认是新提醒启动，并非旧界面一直没退出。

源码存在可触发该现象的路径：返回操作关闭会话后，排队或过渡窗口事件可以重新创建目标应用会话；30 秒返回承诺提醒直接展示，没有普通延迟提醒的前台检查。该路径与日志现象、仅消耗一次普通额度相符，但旧安装包没有记录对应分支标识，不能将推断当成设备分支已确证。

## 本轮修改

1. 新增 `ReturnNavigationGuard`，在关闭会话之前标记返回过渡。MainActivity 的恢复／暂停／销毁同步更新保护状态，恢复时刷新实时前台缓存为回神。
2. 主界面恢复后，只要仍处于 resumed 状态，外部窗口事件不能触发新提醒。离开主界面后，仅允许晚于离开时刻的事件通过。使用 uptime，与 AccessibilityEvent.eventTime 相同时间基准。
3. 导航过渡最多保护 3 秒，防止导航失败后永久停止守护；这不是固定延迟所有提醒。主界面恢复后由生命周期接管保护，不受这 3 秒限制。
4. 无障碍入口在更新前台缓存、重显待处理提醒之前过滤返回期间的外部事件；忽略比已有应用事件更旧的窗口事件。队列中的事件也携带原始时间，交给前台验证使用。
5. AppSessionCoordinator 在建立新会话前、数据库及任务检查后、即时提醒前检查前台；校验失败时不展示、不消耗承诺提醒，已创建的过渡会话关闭。同包旧事件也不能取消正确的离开确认。
6. 保留 30 秒内真正重新进入原应用时的一次强制提醒，继续使用 FORCED_REDISPLAY，不改变普通额度计算。未修改休息计时或 UI。

## 手机验收顺序

1. 守护开启、出现提醒后点击“回到任务”，留在回神超过 30 秒：不应自动再弹一个提醒。
2. 回到任务后主动退出回神，在 30 秒内重新打开同一受守护应用：应触发一次返回承诺提醒，普通额度不应额外增加。
3. 不设置当前任务，重复前两项：守护仍生效。
4. 超过 30 秒后重新打开受守护应用：按正常延迟／额度处理。
5. 再检查“休息 5 分钟”到期提醒。该问题此前未取得完整触发链，本次不能认定已一并修复。
