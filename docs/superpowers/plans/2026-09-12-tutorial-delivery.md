日期：2026-09-12。项目：`D:\Project\Focus-App-UI-improve`；分支：`codex/ui-optimization`。

## 本轮交付

三个独立子任务分别完成公共视觉组件、教程状态与保存逻辑、七步页面及导航；主任务已将交付文件整合到项目，并修正接口和流程问题。不是只留在 work 目录中的草稿。

教程顺序：欢迎 → AI 配置 → 任务 → 应用选择 → 文案生成 → 权限 → 开启守护与主动体验。

- 欢迎页使用标题、幼芽／山丘静态矢量插画、三张介绍卡；其余页面使用同一套主题与组件，支持现有日夜主题。新增组件预览和完整欢迎页日夜、权限页大字体预览源码，尚未渲染。
- 采用现有 MainActivity 和 Compose 步骤切换，不新增 Activity、网络图片、动画库或存储依赖。渲染内容与 ViewModel 接线分开，应用列表按需加载图标并使用有界缓存。
- 为简化实现，进度沿用项目现有 SharedPreferences 方式，没有引入原计划建议的 DataStore。旧 onboarding_done 保留启动入口兼容含义；tutorial_v1 单独记录步骤、配置完成与实际体验状态。API Key 继续使用原 ApiKeyStore，不写入教程进度或页面恢复状态。
- AI 支持复用现有服务类型（DeepSeek／OpenAI／通义／自定义）、地址、Key、模型和连接测试。连接失败后可直接重试；实际远端生成成功并入库后才显示文案就绪。一次教程会话内重试失败的生成，会复用已成功部分；进程重建后仍需重新验证连接和生成状态。
- 可选择已有任务或保存真实时段任务；原任务完成／删除后可以保存替代任务。保存采用稳定待提交 ID，减少中断重试造成的重复任务。
- 应用选择使用真实安装列表，保存到当前应用组；不会重置提醒额度，重看时不会改到历史教程应用组。
- 权限页检查悬浮窗、无障碍、使用情况访问、通知、电池优化，提供系统入口和返回后刷新。后台豁免是建议项，不能代表厂商后台限制全部解除。
- 完成按钮要求当前 AI、任务、已保存应用、缓存、必要权限和应用内检测状态就绪。是否立即开始专注由用户主动选择；没有当前时段时默认 30 分钟，有当前时段时遵循原任务结束时间。
- 新用户配置过程中不提前启用守护；旧用户重看不自动关闭守护。实际保存影响配置的变化会使旧完成／体验状态失效，相同保存和单纯浏览不会清除状态。
- 首页提供待完成教程入口，设置保留“使用教程”。完成页可主动打开所选应用；再次进入／返回教程时核对真实展示与行为记录。休息、有目的使用、返回等有效决策都可用于确认体验，不把权限已开或应用已启动当成体验成功。

## Android Studio 验收顺序

1. 构建并查看欢迎页日夜及权限大字体预览，检查小屏、键盘与底部按钮。若编译报错，保留第一处错误及完整文件位置。
2. 使用没有旧配置的测试安装走一遍七步；检查“稍后继续”、返回上一步和进程重建后继续，不应重复创建任务。
3. 测试错误 Key／模型、网络失败与重试；生成完成后断网，再在有效任务期间打开所选应用，确认读取本地 AI 文案。
4. 从系统权限设置返回，状态自动刷新；拒绝必要权限时不能完成开启守护。未知厂商后台状态不伪装成全部已开启。
5. 开启守护并主动打开应用：等待当前延迟 → 呼吸 → 提醒 → 选择行为；返回教程后检查体验状态，再看统计是否只记录一次。
6. 老用户从设置重看，确认不会自动改变守护、任务或应用组；保存实际变化后要求重新验证，保存相同数据不清除完成状态。
7. 回归“回到任务后重复弹提醒”和“休息 5 分钟后到期提醒”；本轮教程接入不能代替这两个问题的真机验证。
