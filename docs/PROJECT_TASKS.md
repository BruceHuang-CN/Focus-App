## 当前产品目标

当前最高优先级只有两条：

1. 准确、低耗电地识别目标应用进入、停留、离开和再次进入。
2. 可靠地触发、展示、恢复提醒，并记录用户选择后的真实结果。

核心闭环：

```text
当前任务 → 打开分心 App → Focus 提醒
→ 回到任务 / 有目的使用 / 休息一下
→ 30 秒和 120 秒后评估是否有效
```

小球动画、复杂养成、统计扩展和非必要视觉调整不能阻塞上述闭环。

## P0-A：无障碍单模式检测与 Guardian 状态机

- [ ] 删除用户可见的 UsageStats 兼容模式、轮询服务和相关模式选择；旧设置迁移到无障碍模式。
- [ ] 只把可信的应用窗口事件送入 Guardian：过滤 Focus 自身、输入法、系统权限页、通知栏、透明 Activity 和短暂覆盖窗口。
- [ ] 将进入目标 App、疑似离开、确认离开、快速返回和应用内 Activity 切换收敛为一个可测试状态机。
- [ ] 明确一次“打开”的口径：确认离开后再次进入才增加次数，应用内部页面切换、旋转和提醒覆盖不增加。
- [ ] 建立 `ACTIVE / DEGRADED / PERMISSION_REQUIRED / STOPPED` 健康状态，并显示证据和恢复入口。
- [ ] 无障碍事件缺失或服务失联时停止推断精确使用结果，不用第二套轮询伪装为实时检测。
- [ ] 恢复进程启动时的开放会话；无法证明仍在目标 App 时安全结束或标记证据不足。
- [ ] 双开应用默认归入同一应用族；能够可靠区分时仅增加本地别名和实例统计，不拆分 AI 文案缓存。
- [ ] 对无法区分的同包名/工作资料实例明确显示能力边界，不伪装为精确识别。

## P0-B：干预事件、提醒展示和按钮排列

- [ ] 新增不可变 `CurrentTaskSnapshot`，提醒触发后任务标题、目标和上下文不随界面重绘漂移。
- [ ] 新增 `InterventionEvent` 聚合模型，独立记录触发、展示、决定、计时、观察和最终结果。
- [ ] 为每次提醒生成稳定事件 ID；重复调度、Activity 重建和多路唤醒只能确认一次展示。
- [ ] 提醒页只显示三个主操作：`回到任务 / 有目的使用 / 休息一下`；Ignore 不作为按钮。
- [ ] 三个按钮使用全部 6 种排列，排除与上一次完全相同的排列。
- [ ] 同一次提醒重新显示、旋转、进程恢复或 Compose 重组时保持原排列。
- [ ] 设置页增加“随机排列提醒选项”；新安装和所有旧版本升级均默认开启，只有用户主动关闭才固定顺序。
- [ ] 将实际按钮排列写入干预事件，以便统计时排除位置干扰。
- [ ] 无法显示 Activity 时记录 `DISPLAY_FAILED`，并按系统能力转为通知或待恢复状态，不能计为用户忽略。
- [ ] 额度只在提醒真正展示后消耗；重置额度不得删除历史干预事件或使用统计。
- [ ] 保留一个合并按钮“重置提醒窗口和 AI 文案”：一次操作同时恢复当前窗口额度、重置本地文案轮换并刷新当前任务 AI 文案包。

## P0-C：三个决定、任务返回和持久计时

### 回到任务

- [ ] 为任务增加可选返回目标和安全的任务级跳转信息。
- [ ] 优先打开当前任务预设目标；失败时按 Focus 当前任务页、桌面或用户指定应用执行明确兜底。
- [ ] `MainActivity` 和导航层必须真正消费任务 ID，不能只把 ID 放进 Intent 后停留在普通首页。
- [ ] 记录请求目标、实际目标、失败原因和最终跳转结果。

### 有目的使用

- [ ] 用户从 4～5 个本地预设目的中选择，不要求在提醒现场输入长文本。
- [ ] 选择后立即关闭提醒并留在原 App，持久化目的、开始时间、截止时间和允许时长。
- [ ] 到期前不重复弹窗；到期时重新检查当前应用和 Guardian 健康状态。
- [ ] 支持快速延长 5 分钟；连续延长两次后必须重新确认目的。

### 休息一下

- [ ] 选择后关闭提醒并进入全局暂停，不在休息期对其他目标 App 重复干预。
- [ ] 到期时仍在目标 App 则重新提醒；已经回到任务路径则静默记录 `IMPLICIT_RETURN`。
- [ ] 锁屏、电话和系统界面打断时记录 `INTERRUPTED` 或待恢复，不算 Ignore。

### 计时与恢复

- [ ] 计时依据持久化截止时间重算，不依赖“每秒减一”的 UI Tick。
- [ ] Activity 重建、进程回收、设备重启和时钟变化后恢复仍有效的目的使用或休息状态。
- [ ] 所有 AlarmManager、WorkManager 和进程内任务使用同一事件 ID 原子去重。

## P0-D：30 秒/120 秒观察和 Ignore 语义

- [ ] 在决定后建立 30 秒和 120 秒观察点，保存当时前台证据、健康状态和任务路径判断。
- [ ] 原始结果只允许：`NO_RESPONSE / BYPASSED / IMPLICIT_RETURN / DISPLAY_FAILED / UNKNOWN / INTERRUPTED`，并保留明确主动决定。
- [ ] 只有 `NO_RESPONSE` 和 `BYPASSED` 汇总为 Ignore。
- [ ] 无障碍失联、进程冻结、锁屏、电话、系统页面、显示失败和证据缺失不能算 Ignore。
- [ ] “已使用几分钟”“今天第几次打开”“本窗口第几次提醒”分别定义口径；证据不足时选择不含数字的文案，禁止猜测。
- [ ] 统计查询以干预事件为来源，旧 `AppUsageSession.userAction` 只作为迁移兼容字段，不再承担完整结果语义。
- [ ] 统计按钮位置与结果时，可使用已持久化排列校正位置偏差。

## P1：任务级 AI 多阶段文案

- [ ] 所有目标 App 和双开实例共用当前任务的一套 AI 文案包，不按 App 或固定场景类别分别请求。
- [ ] 缓存粒度为“当前任务快照 + 提醒口吻 + Prompt 版本”。
- [ ] 一次请求生成初次提醒、目的使用到期、延长到期和休息结束等多阶段文案。
- [ ] App 名称、目的、允许时长、实际时长、打开次数和提醒次数在本地填充，不产生额外 Token。
- [ ] 本地从缓存变体中选择文案并尽量排除上一条，不在每次弹窗时请求 AI。
- [ ] 网络失败、解析失败或没有 API Key 时立即使用本地模板，不阻塞检测、跳转、计时和提醒。
- [ ] 合并重置按钮只重新生成当前任务的一套文案；生成失败时保留旧缓存，同时仍完成额度重置。

## P1：诊断、双开校准和隐私

## 逆向材料使用边界

允许借鉴可观察行为和架构思想，例如事件驱动、集中状态判断、截止时间计时、幂等调度、重启恢复和中断分类；实现必须基于本项目需求与公开 Android API 独立编写。

禁止复制反编译源码、类结构、方法、文案、资源和专有算法；禁止引入 1×1 Activity、隐蔽自启、防卸载、按键劫持、冒充系统服务、无必要界面文本读取或绕过 TLS 校验等做法。
