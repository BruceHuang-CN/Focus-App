# Focus-App 任务清单

> 更新日期：2026-08-13
> 当前原则：先修复提醒可靠性，再继续低优先级功能；保持低内存、低耗电，不增加高频后台轮询。

状态说明：

- `[x] 已实现`：代码已提交；不等同于已通过本轮真机回归。
- `[ ] 待修复/待实现`：尚未完成，或当前真机行为仍不符合预期。
- 用户当前采用 Android Studio 自行编译和集中真机测试；除非明确要求，不为每次文档或小改动运行 Gradle。

## 当前最高优先级：提醒可靠性

- [ ] **P0：稳定稍后提醒所绑定的目标 App 会话。** 用户选择 1/5/10 分钟或自定义分钟后，临时 Focus 弹窗、键盘、权限窗口和通知栏不能误关会话或取消提醒。
- [ ] **P0：真实离开前执行一次延迟复核。** 检测到非目标窗口后等待 1.5 秒并复核真实前台；目标 App 已恢复则继续计时，仍为其他 App 才确认离开。
- [ ] **P0：真正离开目标 App 后取消本次稍后提醒。** 不发送到期通知，也不弹出提醒；关闭守护或目标应用移出守护范围时同样取消。
- [ ] **P0：补齐稍后提醒回归场景。** 覆盖自定义 3 分钟、临时弹窗、真正离开、快速离开后返回、进程重启和关闭守护。
- [ ] **P0：修复额度统计模型。** 当前一个会话只保存一个 `remindedAt`，重复提醒可能覆盖或误计数；改为独立提醒事件记录，并让“重置额度”只重置当前统计周期，不篡改历史使用数据。
- [ ] **P0：减少无障碍事件造成的碎片会话。** 对键盘、系统弹窗、透明 Activity 和快速窗口切换增加短暂防抖与前台包名复核，避免首次延迟尚未到期就错误结束会话。

## 后台与通知稳定性

- [ ] **P1：增加守护状态诊断。** 首页或设置页显示守护开关、无障碍服务、电池优化白名单、通知权限、最近一次检测时间和最近一次后台停止原因。
- [ ] **P1：区分“从最近任务划走”和“系统强制停止”。** 已确认强制停止后 Android 会结束进程和服务，后台锁定与电池白名单也无法阻止；补充用户可见说明，避免把 Android Studio 的 Stop/重新安装误判为后台保活失败。
- [ ] **P1：进程恢复时校验并恢复调度。** 应用重新启动后读取未到期的稍后提醒和最新守护配置，恢复仍有效的任务，而不是一律结束旧会话。
- [ ] **P1：通知到期行为统一。** 任务提醒通知使用高优先级渠道、点击后打开 Focus 对应状态页；检查不同厂商的通知横幅权限，但不承诺绕过系统强制停止。
- [ ] **P1：主流 Android 真机回归。** 至少覆盖 realme/OPPO、小米、vivo、三星或原生 Android 中可获得的设备，并记录各厂商额外后台权限入口。

## 集中真机测试清单

- [ ] 选择自定义 3 分钟稍后提醒并持续停留在目标 App，3 分钟后收到提醒；临时系统窗口不能取消它。
- [ ] 选择 1/5/10 分钟后，确认实际间隔与选择值一致；真正离开目标 App 后，到期时不发通知也不弹窗。
- [ ] 额度重置后显示明确成功提示；连续触发不应只提醒一次，也不应要求重复重置。
- [ ] 强制提醒开启时，返回键、Home 键、通知、权限弹窗和其他悬浮窗不会把提醒当作已处理。
- [ ] 强制提醒关闭时，普通模式按设计退出，且额度只在真正展示/处理提醒时消耗。
- [ ] 返回桌面、返回 Focus、返回指定应用均跳转到正确目标；更换指定应用不会意外退回设置首页。
- [ ] 从最近任务划走 Focus 后检测/通知行为符合系统能力；Android Studio Stop 或系统强制停止后明确显示需要重新开启。
- [ ] 应用组切换后，检测目标、提醒额度和首页状态一致。
- [ ] 使用统计在真实使用若干分钟后与系统使用情况大致一致，并记录厂商差异。
- [ ] 对比守护开启/关闭时的待机耗电、内存和前台服务状态。

## 已知边界

- Android 系统或 Android Studio 对应用执行“强制停止”后，应用进程、无障碍以外的服务和 WorkManager 都不能自行运行；后台锁定和电池白名单不能绕过该系统限制。
- 不通过持续高频轮询换取表面保活；优先采用系统事件、一次性 WorkManager、通知和状态恢复机制。
- 在未获得二维码、链接或收款信息前，不填入任何真实外部联系方式或收款信息。
